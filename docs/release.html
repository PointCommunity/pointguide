Release and rollback

A release is one clean PointGuide commit, one locally built Linux AMD64 image, one Zot digest, and one reviewed GitOps promotion path.

Release gates

  1. Run the full source, security, database, corpus, browser, and production-build checks.
  2. Commit and push the exact source tree.
  3. Export that clean commit and build locally with Podman for linux/amd64.
  4. Smoke the image as non-root with PostgreSQL migrations, health, readiness, and clean shutdown.
  5. Push to Zot, resolve its immutable digest, and record source revision plus digest.
  6. Update canary from current Gitea homelab origin/master, reconcile Argo CD, and verify the exact digest and whole-cluster health.
  7. Promote the same digest to production—never rebuild—and repeat application, edge, Argo, node, and Ceph checks.

Runtime configuration

Required production values include DATABASE_URL, Cloudflare team domain and audience, provider encryption key, corpus checkout/revision, and server-only Codex credential storage. Git and supplemental web access remain feature-gated.

Rollback

Revert the GitOps image digest to the last verified retained digest. Do not rebuild a historical tag. Reconcile, confirm the old digest is running, then repeat readiness, restart, Argo, node, and Ceph verification.

Repository-writing worker

The worker accepts only an approved exact-content proposal for an active PointCommunity/* source repository, allow-listed paths under data/, docs/, research/, or skills/, and the source's fixed indexed commit. It verifies the repository origin, creates a branch and pull request, and never merges or force-pushes.
