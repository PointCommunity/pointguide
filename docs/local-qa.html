PointGuide local QA

The agent runs local QA on brimdor's Apple Silicon Mac. PM Testing takes place in Canary for application releases. Framework adoption and updates run agent verification and publish source without application deployment or PM Testing.

Prepare an isolated test session

  1. Record the exact source commit and Git tree. Create a disposable worktree from that candidate, inventory task-owned resources, and install the pinned dependencies with npm ci. Do not copy credentials or environment files into it.
  2. Use PostgreSQL 17's local binaries to initialize a fresh temporary data directory with a fixture-only database user. Bind the server only to 127.0.0.1 on a free port. Create pointguide_test. Export matching DATABASE_URL and TEST_DATABASE_URL pointing at that exact disposable database. Never reuse a production or shared database.
  3. Run npm run migrate, then the complete configured suite: npm run check, npm run test:e2e, npm run security:check, npm audit --omit=dev --audit-level=high, and git diff --check. Google Chrome must be installed and port 3100 must be free. Playwright starts and stops the fixture-authenticated local server.
  4. Inspect test counts and confirm the database integration tests actually ran. Viewport-specific skips in browser tests are intentional; missing database coverage is not a pass. Capture command exit codes and source/tree identity in the maintenance PR or application Issue.

Cleanup on success and failure

  1. Stop the disposable PostgreSQL instance using pg_ctl -D with the exact owned data directory. Verify the process has stopped and its localhost port is closed before removing the directory.
  2. Verify Playwright's port 3100 is closed. If recovery is needed, identify only the recorded test server process and its descendants before stopping them.
  3. Remove the owned test worktree, dependency installation, build output, browser captures and logs after preserving concise results. Remove only task-owned images and containers by exact identity. Do not run global prune or remove another application's resources.

Application release images

Application candidates additionally use the local Podman clean-archive AMD64 build in the PointGuide Canary release skill. Inspect architecture, user 1000, SOURCE_REVISION, and the installed GitHub CLI. Publish the exact image once and verify its registry digest; Production promotes that same digest after exact Canary approval. Framework-only maintenance does not build or deploy a release image.
