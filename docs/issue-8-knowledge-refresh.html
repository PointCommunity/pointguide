Issue #8: Pull latest knowledge

Approved scope: Add a Pull latest knowledge button for linked repositories. The Knowledge page refreshes all active registered sources on demand. No timer, upstream write, archive/relink workaround, or application deployment is needed for subsequent refreshes.

Design and state

  1. An authenticated Trainer, Admin, or Owner submits a same-origin POST. The server takes the active-source list and streams per-source progress/results. It processes repositories sequentially, fetching up to four files concurrently within one repository. The button prevents duplicate local submission; optimistic source versions reject conflicting server-side submissions.
  2. Resolve each default branch to one immutable commit, then fetch its tree and bounded text files at that commit. Enforce 2 MiB per text file, 32 MiB total downloaded text, 1,000 evidence files, and a two-minute repository timeout. These bounds accommodate PointAudio's 7.6 MB M32 text plus REAPER. Oversized, unavailable, truncated, or invalid required content fails the repository update rather than silently dropping knowledge.
  3. Reuse the pinned Next.js HTML parser without executing HTML. Remove scripts/styles/navigation. Preserve page blocks, inventory authority/version, capture dates, source paths, content digests, and the immutable commit in chunk identities and locators. Verify applicable text checksums; binary source attachments are not downloaded or represented as verified text.
  4. Validate outside the database transaction. At publication, compare source identity, active status, and version, replace its indexed chunks and report together, and write an audit event. Preserve all previous content if validation, concurrency, or publication fails. Revalidate even an unchanged upstream commit so damaged or legacy snapshots can be repaired.
  5. Read source records and chunks from one consistent database snapshot. A refreshed PointAudio snapshot replaces the old built-in evidence for all subsequent answers/training; until its first successful refresh, preserve the validated built-in fallback. Never combine different PointAudio commits. Retain historical answers. Source proposal bases use the current source record.
  6. Report Updated, Already current, or Failed per repository, with last successful check and the current committed revision. Failed refreshes leave old content and metadata intact; retry is safe. Request interruption aborts outstanding fetches; an already committed repository stays committed. Another click resumes by checking the current state.

Implementation slices

  1. Tests for immutable retrieval, complete indexing, text integrity, HTML/page extraction and failure bounds; implement validator/content normalization.
  2. Tests for atomic source replacement, snapshot consistency, concurrent changes and legacy fallback; implement store/service integration.
  3. Tests for authorization and streamed results; add the route, Knowledge button, accessible states and browser scenarios.
  4. Run real PointAudio and PointPlanning indexing checks, PostgreSQL integration, full source/security/browser gates, local image smoke, then governed Canary and whole-cluster verification.
