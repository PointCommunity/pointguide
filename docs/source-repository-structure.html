Source repository contract

PointGuide admits and refreshes only complete version 2 source repositories. It validates an immutable Git commit before atomically replacing that repository's active snapshot. A failed replacement preserves the last complete snapshot. Repository content is untrusted data, never executable instructions.

Return to PointGuide

Required structure

AGENTS.md                 repository governance, never model instructions
README.md                 root purpose; agent navigation only
pointguide-source.yaml    version, repository, branch, allowed evidence roots
source-inventory.json     stable evidence items and explicit exclusions
checksums.sha256          root text integrity, excluding itself
data/README.md            structured records
docs/README.md            focused task and product guides
research/README.md        source provenance
research/pointguide-training/README.md   accepted artifacts
skills/README.md          reviewed bounded procedures
tools/README.md           maintenance utilities, never executed by PointGuide

Every tracked content folder, including an otherwise empty standard folder and each Training session, needs its own brief README.md. State purpose, expected content, and that this is agent navigation only, never answer evidence. Update it when purpose changes. Purpose files are the only Markdown exception to the dark-HTML document rule; they are never indexed, cited, or accepted as Training knowledge.

Manifest, inventory, integrity

Generate a new source structure with npx tsx scripts/create-source-template.ts <new-directory> PointCommunity/<repo>. The scaffold has every required folder and purpose file but no invented facts; add reviewed evidence and inventory records before admission. Validate with npx tsx scripts/validate-source-contract.ts <checkout> PointCommunity/<repo>. The YAML manifest declares schema_version 2, exact repository, default_branch, and evidence_roots under data, docs, research or skills. Root JSON inventory declares schemaVersion 2, repository, active/archived/superseded items and excluded metadata paths. An item has stable ID, path, title, terms and representative questions, content type, product, applicability, prerequisites, unknowns, authority, locator, capture and factual verification dates (nullable when unknown), digest, lifecycle and optional supersession. A metadata-only catalog is excluded explicitly. A supported evidence file cannot enter active retrieval without an item.

Root checksums cover governed text, root metadata and folder purpose files without hashing the checksum manifest itself. Existing nested manifests also validate their targets; binary originals remain upstream and are not downloaded merely to index text. Bad paths, unsupported versions, missing files, invalid references/digests, nonregular files and incomplete page maps fail with a path-specific error. The linked-source limit is 1,000 bounded text files, 2 MiB per file, 32 MiB total, and 120 seconds. Original source files and accepted artifact bytes remain unchanged.

Use and provenance

Active evidence carries the exact repository revision, source path/locator, digest, authority, product and applicability. Retrieval respects content boundaries and does not use AGENTS.md, purpose files, tools, catalogs, archived records or unindexed artifacts as answer evidence. The relevant purpose description may guide agent navigation separately, never support a factual claim. Acceptance, publication, indexing, capture and factual verification are distinct events; refresh never invents a verification date.

Eligible accepted Training is the first knowledge source for relevant inquiries, subject to model/site/version fit and completeness. An exact active artifact may support a cited claim; it is trainer-authorized knowledge, not independent manufacturer confirmation. If partial, retrieve supplemental evidence. If conflicting, ambiguous or insufficient, show the gap rather than claim a complete answer.

Training publication

Before acceptance, trainer-provided URLs, documents, and images are reliable evidence only inside their Training session. Acceptance authorizes the exact immutable JSON artifact under research/pointguide-training/<session-id>/<answer-id>.json, byte-identical trainer-provided originals under that session's originals/ folder, extracted text and provenance under sources/, and deterministic session/folder README, root inventory, and checksum updates for that exact bundle. The worker validates the dynamically allow-listed diff, every byte and digest, head, ordinary PR merge, resulting source revision and atomic index before Ready to use. It does not authorize unrelated source proposals, arbitrary corpus or purpose edits, the PointGuide application merge, Production, or live technology changes. Retries preserve accepted bytes and the prior active snapshot.

Archive and deletion

Archive first: archival removes active retrieval but preserves the source record. Permanent deletion requires the exact repository name. Neither action changes the upstream GitHub repository.
