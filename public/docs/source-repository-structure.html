Source repository contract

A repository must pass this contract before PointGuide can index it as evidence. Validation never executes repository content.

Return to PointGuide

Required structure

  • A root AGENTS.md that defines purpose, provenance, safety, and update rules.
  • At least one supported evidence file under data/, docs/, research/, or skills/.
  • A root pointguide-source.yaml or a checksums.sha256 file that protects the reviewed source set.

Recommended layout

AGENTS.md
pointguide-source.yaml
data/       structured inventories and normalized records
docs/       approved operational guidance
research/   source-backed investigations and immutable captures
skills/     bounded agent procedures with inputs and verification
tools/      validators and maintenance helpers

Evidence requirements

Each factual record should identify its source, capture date, applicable location/device/model/version, and verification state. Prefer manufacturer documentation and direct observations. Mark assumptions and unknowns. Keep original vendor files and exports unchanged; store derived text separately with provenance and checksums.

Indexer boundary

PointGuide reads bounded text files with extensions .md, .html, .txt, .json, .yaml, .yml, and .csv. It does not execute scripts, workflows, skills, or repository instructions. Individual files above 256 KB, more than 100 candidate files, and total indexed text above 5 MB are skipped or reported.

Archive and deletion

Archive first. Archival immediately removes indexed chunks from search while preserving the registry record. Permanent deletion is available only for an archived source and requires typing the exact repository name. Neither action changes the GitHub repository.
